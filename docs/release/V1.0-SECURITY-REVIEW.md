- **Base reviewed:** `main` at `e645be8`. The code is identical to `67ce701`, where the evidence pack was taken. `e645be8` adds only that pack and one `CHANGELOG.md` line.
- **Date:** 2026-11-21.

This record gives the verdicts, the findings and the closing statement of the V1.0 security review, as defined in
[ADR-0018](../adr/ADR-0018-v10-stabilization-multi-agent.md) section 5. The evidence pack collected the facts without
judging them. The auditor checked the two findings of highest weight in the code itself: SR-01 at `Engine.Audit.ps1:89`
and `:808`, and SR-02 at `Engine.Audit.ps1:99` and `Engine.Clean.ps1:174`. The auditor also checked the elevated
relaunch at `Engine.Recover.ps1:1505-1530`.

## Findings

Each finding is fixed in round V10-S6c, unless "Fix" says otherwise. A fix that changes behaviour stays behind a gate, or
proves that observable behaviour is unchanged (ADR-0018 5.3).

| Id | Severity | Component, item | Finding | Fix |
|---|---|---|---|---|
| **SR-01** | Medium | Audit, item 3 (provider registration) | `TempSubdir` is checked only against `^[A-Za-z0-9._-]+$` (`Engine.Audit.ps1:89`), so several values that are not a plain child folder of TEMP pass:<br>• `.` and `..`. The base is `Join-AtmPath <TEMP> <TempSubdir>`, normalized (`:808`). A provider declaring `..` would make the parent of TEMP its base, and `.` would make TEMP itself the base. Its first-level folders then become scopes, and its second-level folders roots, under the provider's patterns.<br>• A trailing dot, which Windows strips, so the value aliases another name.<br>• Reserved device names, with or without an extension (`nul`, `con`, `com1`, `nul.txt`). Under Windows PowerShell 5.1, `[IO.Path]::GetFullPath('C:\T\nul')` returns `\\.\nul`, checked by the auditor. The value then reaches the normalization as a device path.<br>No shipped provider does this. V1.0 makes third-party providers a supported extension point, so registration must refuse these values. | `Register-AtmProvider` refuses, with `err.providerSubdir`:<br>• a `TempSubdir` made only of dots;<br>• one ending in a dot;<br>• a reserved device name (`CON`, `PRN`, `AUX`, `NUL`, `COM0`-`COM9`, `LPT0`-`LPT9`, case-insensitive), alone or followed by an extension.<br>This is a stricter validation that no shipped or documented provider uses, so it is a compatible change (ADR-0018 1.4). One conformance case covers each form, and the golden inventory comparison stays unchanged. |
| **SR-02** | Low | Audit and Clean, item 3 | Registering an id that is already registered replaces the earlier provider (`Engine.Audit.ps1:99`). The B1 restricted exception is granted by provider id (`Engine.Clean.ps1:174`). A provider file declaring `Id = 'claude-code'` with another layout would therefore inherit the exception for its roots. In an installed copy only manifest-verified provider files load (`agent-temp.ps1:125-130`), and the installation folder is writable by administrators only. In a source checkout, anyone who can add a file to `src/providers/` can also edit the engines. | No code change. This is **accepted as residual R-02**. `docs/PROVIDERS.md` states that the exception follows the id, that an installed copy loads only verified providers, and that a development copy trusts its own source tree. |
| **SR-03** | Medium (behind a closed gate) | Recover, item 5 | The elevated relaunch starts the installed `bin\agent-temp.cmd` through `ShellExecuteEx` with the verb `runas` (`Engine.Recover.ps1:1514-1517`). For a `.cmd` file, the interpreter comes from the file association, and the requesting user's own registry (`HKCU\Software\Classes`) can override it.<br>• **Elevation with consent (same account):** only a program already running as that user is exposed, and the consent prompt names the program that will run.<br>• **Elevation with another account's credentials:** this case is documented as supported (`ELEVATION.md`, "Elevating with another account's credentials"). The requester's registry then chooses what runs as a different, more privileged account. That crosses a real boundary, and the person who types the credentials must notice the program name in the prompt.<br>It is the one place where the product lets an association choose what runs elevated. It is reachable only past the recovery gate, closed in every copy. | Behind the recovery gate, relaunch without any association. Start `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe` by absolute path with `-NoLogo -NoProfile -ExecutionPolicy Bypass -File "<installed root>\agent-temp.ps1"` and the same fixed arguments. These are the shim's own path and flags (`bin\agent-temp.cmd`). The shim also pins `PSModulePath` to the system module directory. The elevated process must get the same pin without relying on the requester's environment.<br>The static test of the elevated launcher moves to the new target, and so does its manifest-listed check: it must follow `agent-temp.ps1`, the file that runs elevated. Update `ELEVATION.md` PRIV-7. Nothing changes with the gate closed. |
| **SR-04** | Low (documentation) | Clean, Isolate, item 4 | `docs/FORMATS.md` has a privacy statement only for the audit export (`:84-87`). For the logs it does not say that they hold full paths, nor which account fields they record: clean log, discard authorization, isolate, purge, auto-purge and recover. | Add one privacy paragraph per log in `docs/FORMATS.md`: the fields that hold paths or account names, the reason (local operator evidence), and that the logs are never exported by the product. ADR-0016 already covers the recover log; cite it. |
| **SR-05** | Low (documentation) | Diagnose, Presentation, item 6 | The PRIV table of `ELEVATION.md` (`:48-60`) names neither `diagnose` (PRIV-1, PRIV-10) nor the GUI (PRIV-1, PRIV-10, GUI-D5). Their status is recorded only in ADR-0014 and in tests. | Add `diagnose` and the GUI to the PRIV-1 and PRIV-10 rows, with their status and the tests or ADR lines that prove them. |
| **SR-06** | Low (documentation) | Recover, item 2 | The window between the revalidation and the service-control call is not recorded as a residual. A service can change state in it, for example started or reconfigured by another process. The engine reads back the outcome, and the R2 and R3 outcomes cover a state other than the expected one. The residual still has no entry in `SECURITY-MODEL.md` "Recovery gate" or in ADR-0016 section 9. | Add the residual to `SECURITY-MODEL.md` "Recovery gate": the window, why it cannot be closed (the SCM has no compare-and-start), and the read-back outcomes that cover it, with their tests. |
| **SR-07** | Low (documentation) | Installer, item 2 | `Remove-AtmOwnTree` (`install/InstallCommon.ps1:170-186`) checks for reparse points and then deletes recursively in a second step, by name. A swap between the two steps is not excluded by the code, and the residual is not documented. The parent of the target is checked not to be writable by ordinary users (`:619-623`), so only an administrator could make the swap. | Record the residual in `SECURITY-MODEL.md`, in the installer section: the two steps, the parent ACL precondition that confines the swap to administrators, and why the installer does not use the deleter (it runs before and after the product is in place). |
| **SR-08** | Info (test hardening) | All, item 3 | The single-assignment tests of the nine gates match only `<name>\s*=`. A gate set through `Set-Variable`, `New-Variable`, `[ref]`, `Get-Variable ... .Value =` or `$script:` scope tricks would escape that pattern. `src` uses none of these today. | Extend the static gate test to refuse, anywhere in `src` and `install`, `Set-Variable`, `New-Variable`, `Remove-Variable` or `Get-Variable` that names a gate, and any `[ref]` of a gate. Plant each form in a copy to prove the refusal. |
| **SR-09** | Info (documentation) | Records | Several records are stale against `main`, as the evidence pack found: <br>• the V0.2 audit table rows F-04 ("not closed", although T1 was published in 0.3.0), F-05 and F-14 ("proposal", although they are fixed on `main`, unpublished); <br>• the V0.2 audit gate table, which lists four gates where there are nine; <br>• `V0.3-RC.md:121`, which lists the 0.3.0 publication as OPEN although 0.3.0 is published; <br>• the 2026-11-01 incident record, which says the product moves nothing, although the isolation engine exists behind its closed gate. | Leave the historical text unchanged. Append a dated "Status at V1.0 review (2026-11-21)" note to each record with the current state and a link to this review. **F-04 is closed on record here:** T1 shipped in 0.3.0: the T1 entry is at `CHANGELOG.md:223`, and `CHANGELOG.md:6` records 0.3.0 as published. That meets the condition `V0.3-RC.md:109` set ("closed only once published"). |

## What this review does not cover

These items are the operator's (ADR-0018 section 6). The review neither performs nor replaces them:
- a real UAC consent and a second real administrator;
- a Windows 10 client and Windows 11 x64;
- the privilege rows V4-1, V4-5, V4-6, V4-7 and L-2;
- the real-console acceptance of the TUI (`V0.2-TUI-ACCEPTANCE.md`) and the GUI;
- the V5 pilot of real deletion.

Nothing here opens a gate. Before a gate opens, its own residuals must be reviewed again: R-05 for the export and handle
gates, R-06 for the worktree gate, R-07 for the recovery gate, and the V5 pilot for the deletion gate.

## Closing statement

The review is complete for the nine components and the seven checklist items.
- **No finding of high severity.**
- **Two medium findings:**
  - SR-01: a validation gap at the provider extension point, with no effect on shipped providers.
  - SR-03: an association choosing what runs elevated, behind the closed recovery gate.
- **One low code finding,** SR-02, accepted as residual R-02.
- **Documentation and test-hardening findings:** SR-04 to SR-09.

Every verdict outside those findings is MET, or MET with a residual that is listed for acceptance.

The review is **ready for the maintainer's acceptance** once V10-S6c lands the fixes for SR-01, SR-03, SR-04 to SR-08
and the SR-09 notes. The auditor then checks those fixes and adds a verification addendum below. The round that lands
the fixes does not edit this record.
