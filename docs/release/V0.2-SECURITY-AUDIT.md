# V0.2 security audit (FINAL-A)

Scope: the whole product at `main` `474db7f` plus the FINAL-A branch (V0.2 in development; nothing released; version
0.1.0). Method: code review of every surface below (one sequential read-only audit pass plus the maintainer-directed
review of each finding), adversarial tests on disposable fixtures only (no real TEMP, profile, repository, service,
VM, ACL or registry change; no Git on real repositories; no Restart Manager on real files; D-1 not used). Zero CodeQL
alerts is not evidence of absence of defects: every control below cites a test or a `file:line`.

### F-01 — HIGH — network/device paths from other users' environment reached file APIs (NTLM exposure)

* **Where:** `Engine.Audit.ps1` (`Get-AtmNormalizedPath` called `GetLongPathNameW` before `Test-AtmPathChain`; values
  from `HKU\<SID>\Environment` expanded as is); `providers\ClaudeCode.ps1` (`Get-AtmClaudeConfigDirs`,
  `Get-AtmClaudeSessionEvidence`: `[IO.File]::GetAttributes`, `GetFiles`, `ReadAllText` on `CLAUDE_CONFIG_DIR`;
  `GetExtraTempDirs`: `CLAUDE_CODE_TMPDIR` as is). Reached by audit, preview, clean, diagnose and the TUI.
* **Exploitation:** a local standard user whose hive is loaded sets `TEMP`, `CLAUDE_CONFIG_DIR` or `CLAUDE_CODE_TMPDIR`
  to `\\host\share` (or `\\host@80\x`, WebDAV); an elevated administrator runs any read command (the documented way to
  get full coverage). The administrator's process authenticates to that host (NTLM relay or offline cracking) and
  parses JSON from it.
* **Fix:** `Test-AtmLocalPathForm` (drive-absolute, not a network drive letter, no stream or control character,
  including C1 `0x7F-0x9F`; only the drive type is queried) guards `Get-AtmNormalizedPath` before any API call, and the
  provider skips configuration folders in another form (counted as refused, session evidence marked unreadable with a
  note: a coverage gap, never "no sessions"). A network or device TEMP base is `INVALID` (its raw value is shown with
  control characters replaced). The check is **lexical**: a local path whose component is a directory symbolic link to a
  share passes it. So (review M-3) `Get-AtmNormalizedPath` never traverses a reparse point (only the part before it is
  expanded; the callers' chain checks refuse it), and another user's configuration folder whose chain holds a reparse
  point is not read (counted as refused); one's own folder is read as before.
* **Tests:** "FINAL-A F-01" (refused forms including `\\?\UNC`, `\\.\pipe`, WebDAV, drive-relative, streams and C0/C1
  control characters; no network attempt; refused configuration folder without fallback; inventory base `INVALID`;
  normalization through a junction kept lexical; another user's configuration folder through a junction refused, one's
  own read). A directory symbolic link to a real share was **NOT TESTED** (needs a privilege and a share; a junction
  stands in for the reparse point).
* **Residual:** a mapped drive letter in the administrator's own session is refused as network; a removable drive is
  accepted (local); file reads after the chain check (`ReadAllText` of session files in one's own or another user's
  folder) still open by name, so a component swapped for a symbolic link between the check and the read is not excluded
  (a race against an elevated read; V0.1 behaviour); the normalization has the same window (the chain is read, then
  the long name is resolved). Exploiting it needs a directory **symbolic link** to a share: a junction cannot target a
  UNC path, and creating a symbolic link needs `SeCreateSymbolicLinkPrivilege` (administrators by default) or Developer
  Mode, which narrows the attacker to such accounts or machines. **V0.1.0 (released) is affected**: whether it needs an advisory is a maintainer decision.

### F-02 — MEDIUM — `audit -ExportJson` checked by name, then wrote by name

* **Where:** `agent-temp.ps1` (V0.1 audit export): `Test-AtmOutputPathOutsideBases -MustNotExist` then
  `[IO.File]::WriteAllText` (truncates an existing file).
* **Exploitation:** a user who can write to an ancestor of the destination swaps it for a junction (or an object-manager
  link) between the check and the write while an elevated administrator exports there; the administrator's process
  creates or overwrites a file elsewhere with partly attacker-influenced JSON.
* **Fix:** the same V0.1 rules, evaluated again inside the pinned window, and the file created by `New-AtmPinnedTextFile`
  (below); a refusal keeps the V0.1 message (`cli.exportRefused`, exit 10), now preceded by its code. No rule was relaxed.
* **Behaviour changes (conservative, documented in USAGE):** a race or a `subst` alias is refused; a destination
  directly in a volume root, a parent of 240 characters or more and a network or non-fixed drive are refused (V0.1
  accepted them); an I/O error while pinning is reported as a refusal; the file gets a protected DACL (owner, SYSTEM,
  Administrators), so a file exported elevated may not be readable by the same user unelevated (F-09).
* **Tests:** "FINAL-A: saidas da V0.1" (created; existing refused and intact; inside a base refused; folder swapped for a
  junction refused, nothing in the target). **V0.1.0 (released) is affected** (maintainer decision on an advisory).

### F-03 — LOW — terminal escape sequences from session files

* **Where:** `providers\ClaudeCode.ps1` (project name = leaf of the session's `cwd`; `sessionId`), shown by the audit,
  preview, clean plan and TUI.
* **Exploitation:** any user writes a session file whose `cwd` holds ESC sequences; the administrator's console output
  (including the clean plan) can be rewritten or hidden.
* **Fix:** control characters (`0x00-0x1F`, `0x7F-0x9F`) replaced by `?` at the source (project name, session id).
* **Test:** "FINAL-A F-03/F-06/F-07/F-08".

### F-04 — LOW (latent) — `clean -LogFile` appends by name

* **Where:** `agent-temp.ps1` (destination checked before the plan) and `Engine.Clean.ps1` (`Add-Content` after each
  deletion). Written only after a real deletion, which the deletion gate prevents in every copy.
* **Proposal (not implemented, public semantics):** open the log once, up front, through the pinned creation and keep
  the handle for the run. Changes `-LogFile` from "append to an existing file" to "new file"; a maintainer decision, to be
  taken before the deletion gate can ever open (V0.3).

### F-05 — LOW — a TEMP value can claim another user's base

* **Where:** `Engine.Audit.ps1` (deduplication of bases by path). A user who sets TEMP to another user's folder can be
  attributed that base first; the other user's partitions get `SHARED_TEMP` and cleanup of them stays blocked.
* **Impact:** wrong attribution and permanently blocked cleanup; deletion stays safe (owner gate, `SHARED_TEMP`).
* **Proposal:** attribute a base to a profile only when the folder's owner is that profile's SID, otherwise a discovery
  gap. Changes attribution (V0.1 output): a maintainer decision.

### F-06 — LOW — V0.1 self-exclusion trusted a parent PID without its creation time

* **Fix:** the chain stops at a parent created after its child (reused PID) or whose creation time (or the child's) is
  unknown, so such a process is never excluded from references (the safe side). **Tests:** "FINAL-A F-03/F-06/F-07/F-08"
  and the V0.1 self-exclusion test (now with creation times; an unknown time stops the chain).

### F-07 — LOW — installer verified the source, then copied it

* **Fix:** the source manifest is read once and kept in memory; the source is verified against it, and the staged copy
  (right after the copy, before any local file is added) is verified against the same in-memory manifest
  (`Assert-AtmStagedCopy`; the staged copy has no `manifest.json`, which is regenerated). A file changed between
  verification and copy, or an extra file, is refused. A first version of this fix compared a staged `manifest.json`
  that the copy never creates and refused every installation; CI's install e2e caught it (review B-1).
  **Test:** behavioural on a release-shaped fixture (intact copy accepted, changed and extra files refused) plus the
  install e2e.
* **Residual:** anyone who can write the package folder can also change the installer scripts; the installation
  guidance (an administrator-only folder) remains the control.

### F-08 — LOW — the release build checked only the deletion gate

* **Fix:** the archive is refused unless each of the four gates has a single assignment to `$false`. **Test:** static
  only (the test checks that the build script names the four gates; the refusal itself is exercised by CI's package
  build, which passes).

### F-09 — INFO

* The pseudonym key file is opened by name and its ACL read by name (an ancestor swap is not excluded); the key never
  leaves memory and a refusal is fail-closed.
* The typed clean confirmation reads stdin (`Read-Host`): it proves an explicit phrase, not a human (latent: the
  deletion gate is closed).
* Registry keys are closed outside `finally` on some paths (released at garbage collection after an exception).
* In the job runner, a reader thread still running after its join timeout may race on the output buffer; the job is
  already terminated.
* With an elevated token the owner of a created export is usually Administrators: the protected DACL (`OW`, SYSTEM,
  Administrators) then leaves it unreadable to the same user unelevated (usability).

### F-10 — LOW (latent) — the deletion engine claimed share modes prevent in-place junction conversion

* **Where:** `Native.cs` (`AtmDeleter` comment) and SECURITY-MODEL (*Deletion itself*): "tree directories pinned
  without `FILE_SHARE_WRITE`, so an emptied directory cannot be converted into a junction in place".
* **Evidence:** the review of this audit (M-1) set a junction on a pinned empty folder through another handle opened with
  `FILE_WRITE_ATTRIBUTES` only (`FSCTL_SET_REPARSE_POINT`): share modes govern data access, not that right. Now a
  deterministic fixture test for the safe creation (X-01).
* **Impact:** none observed: the deleter re-checks every pinned directory through its handle before enumerating and
  before deleting, and checks the final path of every file it opens; real deletion is disabled in every copy.
* **Fix:** the claim is corrected (comment and SECURITY-MODEL); the code is unchanged. **Proposal** (before the deletion
  gate can ever open, V0.3): an adversarial fixture test of the deleter with the same in-place conversion.

### X-01 — diagnose export ancestor TOCTOU (P5-B-S gate)

* **Design (FINAL-A):** `AtmSafeCreate` (Native.cs). `Pin()` opens every ancestor top-down without following reparse
  points (`FILE_FLAG_OPEN_REPARSE_POINT`), refuses a reparse point, a non-directory or a redirection (final path through
  the handle), and keeps each open without `FILE_SHARE_DELETE` (cannot be renamed, deleted or replaced while pinned);
  `subst` and non-fixed drives are refused. Share modes do **not** stop another handle with `FILE_WRITE_ATTRIBUTES` from
  turning the pinned (often empty) folder into a junction in place (`FSCTL_SET_REPARSE_POINT`, review M-1): `CreateNew()`
  re-checks the folder before and after creating and refuses (`PARENT_CHANGED`), and the creation never follows a reparse
  point. `CreateNew()` re-checks the folder, creates the file **relative to the folder handle** (`NtCreateFile` with
  `RootDirectory`, `OBJ_DONT_REPARSE`, `FILE_OPEN_REPARSE_POINT`, `FILE_CREATE`) with a protected DACL, verifies it
  through its own handle (not a reparse point, same volume, final path as expected) and only then writes. The policy
  (bases, repositories) is evaluated inside the pinned window.
* **Evidence (fixtures):** renaming the folder or an ancestor while pinned is refused; a folder or ancestor swapped for a
  junction before pinning is refused; a junction (and, where the runner allows it, a file symbolic link) at the file
  name is refused; an existing name is never reused; the DACL is protected; the pinned folder turned into a junction in
  place **inside the window** (deterministic, `FSCTL_SET_REPARSE_POINT` from another handle) is refused with nothing in
  the target; a stochastic race (another runspace swapping the folder with a junction between 150 creations; it attacks
  **before** the pin, not inside the window) never put a file in the junction target; a repository created after a
  by-name pre-check is refused inside the window; a by-name creation in the same situation is redirected (counter-proof).
  Device names with superscript digits (`COM¹`, `LPT²`) are refused as file names.
* **Limits:** `OBJ_DONT_REPARSE` needs a Windows 10 build that supports it (otherwise creation fails closed); the drive
  letter itself is resolved through the DOS device namespace of the session (an attacker able to redefine it is the same
  user); the volume root is not pinned (it cannot be renamed); a refusal after creation can leave an empty file: such refusals
  carry a `CREATED_` code and the CLI says that a file may remain (never that none was created).
* **Status:** mitigated in code and on fixtures. Evidence: the local suite on Windows 10 22H2 (build 19045, AMD64,
  Windows PowerShell 5.1), the CI suite on `windows-latest` with both shells and on Windows 11 ARM64 with Windows
  PowerShell 5.1 (job `test ARM64`, informative: every FINAL-A case passes there, including the in-window FSCTL test;
  its environmental FAILs are reported, not hidden); the install e2e (Windows Server 2022/2025 AMD64, Windows 11 ARM64,
  both shells) installs the package that compiles this code. **ARM64 with PowerShell 7 is NOT TESTED** (the suite did
  not finish in 90 minutes on that runner; the FINAL-A cases were not reached). **The export gate stays closed**:
  opening it needs the maintainer's decision (HUMAN_GATE).

## Privacy notes

* The diagnose JSON (when the export is ever enabled) carries `machine`, `identity.user` and `identity.sid`
  (documented in DIAGNOSE-SCHEMA). Alternatives for a later schema version, not adopted (no silent schema change): a
  keyed pseudonym of the user and machine with the run key, or an opt-in switch to include them. A maintainer decision.
* No secret, token, command line or file content is exported (P5-B contract test; privacy scanner on docs, src and tests).

## Recommendations for V0.2

* Keep the four gates closed in V0.2. The diagnose export may be considered for opening only after the maintainer
  accepts X-01 (code, fixture evidence and the limits above); Windows 10 coverage and a review of `OBJ_DONT_REPARSE`
  support should come first (FINAL-B).
* Decide on F-04 and F-05 proposals and on an advisory for V0.1.0 (F-01, F-02).
