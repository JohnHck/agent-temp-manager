## Scope and limits

* In scope: the V0.2 deliverables of the roadmap (processes, services, resources, virtualization, Git worktrees,
  dependencies, temporary directories extended with runtime evidence, `diagnose` command, TUI view, JSON export,
  identity and elevation display, Claude Desktop provider) and the V0.1 commitment carried into V0.2 by
  `SECURITY-MODEL.md` (*Discovery visibility*: injectable registry sources and a visible note when profile discovery
  is incomplete).
* Out of scope: V0.2.1 (desktop GUI and live monitoring), V0.3 (real deletion), any change to the V0.1 gates,
  classification or deletion code, enabling the release gate, a remote check of publication (may come later as an
  explicit option; never implicit).
* Read-only, always: no deletion, move, rename or modification of user files; no Git fetch, pull, prune, gc, checkout,
  stash or index-writing command; no change to ACLs, services, processes, virtual machines, scheduled tasks or Windows
  configuration; no elevation requested; no network access. The only process the engine may terminate is a Git child it
  started itself, inside its own job object, on timeout (decision D-4).
* Bounded, always: time, files, memory and processes have limits; a timeout or read failure gives `UNKNOWN`/`PARTIAL`,
  never clean (ADR-0001).
* Privacy: no command lines, environment values, tokens, Git configuration values, service command-line arguments or
  file contents are printed or exported.
* Process: small pull requests, full suite on Windows PowerShell 5.1 and PowerShell 7, commit identity check, privacy
  scan, static analysis; noreply commit identity; fast-forward merges of the validated head; no force-push; no bypass
  of branch protection. Merges and releases only with the maintainer's explicit authorization.
* Version: `$script:AtmVersion` stays `0.1.0` until the release-candidate pull request of the FINAL phase sets
  `0.2.0`; until then `main` is development code, not a release.

## Stop conditions (HUMAN_GATE)

As in V0.1, plus: any test or collector that would read a real repository, worktree or another project of the
maintainer's machine (fixtures only; real-machine tests are limited to read-only process/service listings in the
suite's own session); any need to terminate a process the engine did not start; any network access; any change to a
V0.1 gate; a decision listed below that is still open when its phase starts.

does not block a phase, but any local failure that is not explained by a recorded environmental cause does. V0.1 tests stay green and unchanged in every phase, except tests whose expectations a phase explicitly
extends (listed in its pull request).

## Test strategy

* **Isolation:** every write happens in the suite's sandbox (`%TEMP%\atm-tests-<random>`). Git fixtures are created
  there with an isolated configuration (`GIT_CONFIG_GLOBAL` pointing to a sandbox file, `GIT_CONFIG_NOSYSTEM=1`,
  fixed fictional author identity, no remotes except local sandbox paths). The suite never runs Git, the diagnose
  engine or any collector on a real repository, worktree or project of the machine it runs on.
* **Fixture creation vs engine:** only the test code may run mutating Git commands, and only on sandbox fixtures; the
  engine's runner refuses them (allow-list) and the runner spy records every call made by the engine.
* **Mocks:** every collector has an injected source; fixtures are small PowerShell objects with fictional names, PIDs,
  SIDs (`S-1-5-21-1-2-3-...` style) and paths (`C:\Users\alice\...`), never real data.
* **Read-only proofs:** before/after listings with SHA-256 of fixture trees (including `.git\index`), services'
  state snapshot on the real machine, and the existing audit/preview sandbox comparison.
* **Real-machine tests (read-only):** process and service listings of the suite's own session, identity and token
  elevation type; results recorded as observed, never assumed.
* **Native code:** child processes started by the suite inside the sandbox (working directory, held files, 32-bit
  child where available) to exercise ADR-0004 and the bounded runner; nothing outside the sandbox.
* **Both shells and both languages** for every new test area; `NAO_TESTADO` is never counted as a pass.
* **Heavy tests** (1,000+ real worktrees, large trees) behind `-SkipHeavy`; light synthetic equivalents always run in
  CI. A manual CI job (`workflow_dispatch`) for the heavy set is added in P3-E if run time allows.
* **Destructive or heavy experiments** (for example a lazy-fetch or ownership scenario that needs another account) run
  only on disposable CI runners or VMs, never on the maintainer's machine.

## Risks

| Risk | Mitigation | Rollback |
|---|---|---|
| A Git command writes to a repository | Allow-list, `--no-optional-locks`, `GIT_OPTIONAL_LOCKS=0`, read-only proofs with SHA-256 of `.git` on every fixture | Revert the pull request; the engine never ran on real repositories in tests |
| Repository configuration executes code (fsmonitor, filters) | Overrides, D-3 marker test, `UNKNOWN` when not provably prevented | Disable the affected fact (coverage `NOT_OBSERVABLE`) |
| Implicit network (lazy fetch, credential helpers) | `protocol.allow=never`, `GIT_NO_LAZY_FETCH=1`, prompts disabled; test with a watched local promisor | Same as above |
| Reading process memory exposes command lines or environment | Read only the `CurrentDirectory` string; static test on offsets; report only inside indexed paths (D-1) | Reject D-1: working directories stay `NOT_OBSERVABLE` |
| PEB layout differs on an architecture (ARM64 emulation) | Supported combinations only; otherwise `NOT_OBSERVABLE`; CI on Windows 11 ARM64 | Mark the architecture unsupported |
| `NtQueryObject`-style hangs | Handle enumeration rejected for V0.2 (ADR-0004) | - |
| Absence read as "not running" | ADR-0001 rule 3 and its table-driven test | - |
| Unbounded runs on large machines | Caps, budgets and deadline everywhere; scale tests | Lower defaults |
| Privacy leak in export (paths of repositories, service arguments) | Export rules, privacy tests with planted values, warning text; D-5 alternative | Hash/leaf mode |
| V0.1 behaviour changes by accident | V0.1 tests unchanged; diagnose does not touch gates, classes or the clean engine | Revert |
| CI time grows past 30 minutes | Heavy tests behind `-SkipHeavy`; measure per phase | Split jobs |
| Claude Desktop signatures change between versions | Recorded with version and date; absence is `NOT_PRESENT`/`UNKNOWN`, never an error | Update provider data |
