# Agent Temp Manager 0.2.0: release notes (release candidate)

**Status: release candidate, NOT published.** The version is set to `0.2.0` on the release-candidate branch
(FINAL-C). Version 0.2.0 exists only after the maintainer approves publication: the tag `v0.2.0` and the GitHub
Release are created only then, and only that release's zip and `SHA256SUMS.txt` are the published package. Until
then the latest published version is 0.1.0. Portuguese: [V0.2.0-RELEASE-NOTES.pt-BR.md](V0.2.0-RELEASE-NOTES.pt-BR.md).

## What it is

Read-only auditing and preview of the temporary directories that AI coding agents leave on Windows, across every
local user profile, with an interactive dashboard (TUI). V0.2 adds **read-only runtime diagnostics**: what is running
around those directories, with the coverage of every observation.

**Nothing in this version deletes files, terminates processes, stops services or shuts down VMs.** `agent-temp clean`
still runs every safety gate and prints the exact plan, then stops without deleting anything
(`EXCLUSAO_REAL_DESABILITADA_V0_1`, code kept for compatibility).

## What V0.2 adds

* **`agent-temp diagnose`** (and area **D** of the TUI): runtime diagnostics on explicit request, strictly read-only.
  It never asks for elevation, runs no Git and writes no file. A global deadline (`-DeadlineSeconds`, default 300 s)
  skips collectors that have not started; it is **not a maximum duration** (the V0.1 inventory cannot be interrupted
  once started).
* **Processes and sessions:** the identity of this process (user, elevated administrator, token elevation type,
  integrity level, session); agent processes and sessions found through evidence only (provider matchers, session
  registries, the audit's path references, verified parent links), identified as `pid@creationTicksUtc` so a reused
  PID is never taken for the original; resource totals per verified process tree (CPU over a stated interval, memory,
  handles, I/O; an unreadable value is `null` with `PARTIAL`, never 0).
* **Windows services:** only the services that providers declare, read-only (state, start type, account kind,
  process link verified by creation time). Service accounts are not exported (ADR-0012).
* **Virtualization:** the Hyper-V platform and its virtual machines, read-only. Limits: an HCS compute system that is
  not a Hyper-V Manager VM (such as the Cowork VM) is not listed; without the required rights the platform reads as
  `DENIED` or `PARTIAL`.
* **Claude Desktop and Cowork:** a runtime-only Claude Desktop provider (its packaged processes and its service). The
  local `CoworkVMService` is identified by a publicly reported, provisional name (not documented by Anthropic); a
  running service with a verified process is evidence of the local Cowork service, never of a running VM. When
  evidence fits Claude Code and Claude Desktop alike, the attribution is ambiguous and no provider is chosen.
* **Dependency graph:** an in-memory graph correlating that evidence, which explains why a temporary partition looks
  in use. Edges are direct, attributed or uncertain (`[D]`, `[A]`, `[?]`).
* **Temporary partitions with evidence:** `IN_USE` only with direct evidence from a verified process; otherwise
  `UNKNOWN`, which never means free. `NO_DEPENDENCY_OBSERVED` needs every relevant collector to be conclusive, so it
  does not appear while open files and working directories are not observable. The V0.1 class stays next to it,
  unchanged.
* **Multi-user discovery:** Windows profile discovery and its gaps (`profile-discovery`), with injectable sources for
  tests.
* **TUI area D:** busy screen, observation time, categories, details, paging, coverage-aware counts, refresh with `U`;
  navigation never runs the diagnostics again; an earlier result is kept and marked outdated when a refresh fails.
* **Coverage everywhere:** every collector reports `COMPLETE`, `PARTIAL`, `DENIED`, `TIMEOUT`, `NOT_PRESENT`,
  `NOT_OBSERVABLE`, `UNAVAILABLE` or `FAILED`, with reason codes and whether elevation would help (`YES`, `NO`,
  `UNKNOWN`). Only `COMPLETE` and `NOT_PRESENT` are conclusive; **the absence of evidence does not show that something
  is unused**.
* **Privacy:** temporary partitions and agent sessions appear only as keyed pseudonyms (ADR-0010); no path, command
  line, token or session id is shown. `-PseudonymKeyFile` makes pseudonyms comparable between runs.

## Security and integrity improvements

* **FINAL-A security audit** (`docs/release/V0.2-SECURITY-AUDIT.md`), fixed: F-01 (HIGH, network or device paths from
  other users' environment reached file APIs), F-02 (MEDIUM, `audit -ExportJson` checked by name and wrote by name), F-03
  (terminal escape sequences from session files), F-06 (self-exclusion chain), F-07 (installer verified the source,
  then copied it), F-08 (release build checked one gate), F-11 (services and VM link on two clocks). **F-01 and F-02
  also affect the published 0.1.0** (see *Open decisions*).
* **FINAL-B:** F-13 (the post-install verify ran `cmd.exe` found through PATH; now the System32 path), CI artifacts
  sanitized and scanned before upload (fail closed), privilege rows and clean-environment evidence.
* **Installation (R-B5, R-B6):** `verify` and the installer bootstrap run no code whose integrity was not checked first
  (exit code `5` for a missing, altered or unlisted file); update and rollback never destroy the only intact
  installation, keep the older copy until the new one verified, put both back on a failure, and detect an interrupted
  operation at the next run; one administrative operation per installation at a time.
* **Release build:** refuses an archive unless each of the four gates has a single assignment to `$false`.

## What remains blocked (closed gates in every copy)

No option, environment variable or configuration file opens them; source, package and installation are checked.

* Real deletion (`AtmRealDeletionEnabled = $false`).
* Real Git worktree diagnostics (`AtmWorktreeDiagnosticsEnabled = $false`): `worktree-discovery` is `NOT_OBSERVABLE`.
* Real open-file (handle) diagnostics (`AtmHandleDiagnosticsEnabled = $false`): `handles` is `NOT_OBSERVABLE`.
* The diagnose JSON export (`AtmDiagnoseExportEnabled = $false`): refused with `EXPORT_SECURITY_GATE_CLOSED`, exit `10`.

## What remains limited

* **Working directories of processes:** D-1 (PEB read) DEFERRED; `process-cwd` is `NOT_OBSERVABLE`.
* **Claude Desktop:** no real installation validated; the provider is tested on fixtures and injected sources.
* **`CoworkVMService`:** provisional identification by a publicly reported name.
* **Cowork utility VM:** not attributed; the tool does not see it.
* **Windows 11 ARM64, PowerShell 7:** 16 suite cases are not run there (launcher-heavy installation cases and the
  environment probe); they are NOT TESTED on that combination, not passed.
* **TUI:** validated headless only (rendered frames, injected keys); **not accepted in a real console**
  ([V0.2-TUI-ACCEPTANCE.md](V0.2-TUI-ACCEPTANCE.md)).
* **Privileges:** without elevation, other accounts' processes, some services and the virtualization platform may be
  unreadable; reported as `PARTIAL` or `DENIED`, never as "nothing there". Some privilege rows are NOT TESTED
  ([V0.2-FINAL-B-VALIDATION.md](V0.2-FINAL-B-VALIDATION.md)).
* **Durations:** no maximum duration is promised for `diagnose` or for the V0.1 inventory; child calls of the test
  suite outside its job executor have no global deadline.
* **Open findings:** F-04 (`clean -LogFile` appends by name; latent, deletion disabled), F-05 (a TEMP value can claim
  another user's base: wrong attribution, cleanup stays blocked), F-14 (`verify` does not report unlisted files outside
  `providers`; never loaded): decisions pending.
* Scripts are not Authenticode-signed; integrity relies on `SHA256SUMS.txt` and the installed manifest.

Not promised: automatic cleanup, exhaustive diagnostics, or that a partition without observed evidence is unused.

## Install and verify (after publication)

1. Download `agent-temp-manager-0.2.0.zip` and `SHA256SUMS.txt` from the GitHub Release `v0.2.0`; compare
   `(Get-FileHash .\agent-temp-manager-0.2.0.zip -Algorithm SHA256).Hash` with `SHA256SUMS.txt`.
2. Extract into a folder only administrators can write (for example under `%ProgramFiles%`).
3. From an elevated PowerShell started with `-NoProfile`: `install\Install-AgentTempManager.ps1` for a new
   installation, `-Update` over 0.1.0 ([docs/INSTALL.md](../INSTALL.md), [docs/ELEVATION.md](../ELEVATION.md)).
4. Open a new terminal: `agent-temp verify`, `agent-temp version` (shows `0.2.0`).
