head of the pull request, and installed by all six `install e2e` jobs (each checks its SHA-256 against the

## D. Job-executor residual (FINAL-B-S)

* **Today** (`AtmJobRunner.Run`, `src\lib\Native.cs`): after the child exits, the runner waits 2 s / 0.5 s for the two
  reader threads; if either is still running it calls `TerminateJobObject` and sets `JobTerminated` only when that call
  succeeds; then it joins the readers for 5 s each and returns. When that termination fails, the result does not say
  so: `JobTerminated` stays `false`, which is also its value when the pipes simply drained, and nothing says whether
  the readers finished. The harness therefore cannot tell "pipes drained" from "termination failed, output may be
  incomplete". `KILL_ON_JOB_CLOSE` still ends every member when the job handle closes, but it is a backstop, not
  evidence that the explicit termination worked.
* **Not resolvable in the harness alone:** the information is not in the result. Any fix adds fields to the native
  result, which widens the contract of `AtmJobRunner` (also used by the product's Git runner, behind its closed gate)
  and changes the native library shipped in the package. Under the gate's rule this is a **proposal for HUMAN_GATE**,
  not part of this release candidate.
* **Proposal (smallest change):**
  1. `AtmJobResult` gains, additively (no field removed or renamed): `TerminationRequested` (bool),
     `TerminationFailed` (bool), `TerminationWin32Error` (int), `ReadersCompleted` (bool, both reader threads finished
     before the result was built) and `ActiveProcessesAtEnd` (int, from the job accounting just before return).
  2. Both termination sites (deadline and members holding the pipes) set the three termination fields.
  3. Harness (`ConvertFrom-AtmTestJobResult`): `TerminationFailed` → `CHILD_RUNNER_JOB_TERMINATE_FAILED`;
     `-not ReadersCompleted` → `CHILD_RUNNER_OUTPUT_INCOMPLETE`; both FAIL, no PID fallback, nothing started outside
     the job.
  4. Product (`Invoke-AtmGitCommand`, gate closed): `TerminationFailed` → `FAILED`/`GIT_JOB_TERMINATE_FAILED`;
     `-not ReadersCompleted` → `PARTIAL`/`GIT_OUTPUT_INCOMPLETE` (never `COMPLETE` without the whole output).
  5. Tests: normal exit; descendant holding the pipe with successful termination; deadline; external harness sentinel
     intact; limits (memory, processes, time); failure injection through an internal seam that only the test build can
     reach (to be designed and reviewed: a public switch in the shipped library is not acceptable), or else the harness
     mapping on synthetic results only, as today; AMD64 and ARM64, PowerShell 5.1 and 7.
* **Status for publication:** open. Either the proposal is approved and implemented before 0.2.0, or the maintainer
  records an explicit residual-risk decision (impact limited to the test suite and to the closed Git gate; the backstop
  ends every member when the call returns).
