# ATM-V0.1-FINAL: plan and status

Executable plan for finishing V0.1.0: remediation, validation and a release candidate, **with real deletion
disabled**. This file is the status record; every item links to its evidence (pull request, CI run or report).

Status values: `DONE` (criterion met, evidence linked), `IN PROGRESS`, `PENDING`, `HUMAN_GATE` (needs a specific
authorization or an action only the maintainer can take), `BLOCKED` (cannot be met in this stage), `NOT TESTED`.

**A green CI run is not a real validation of installation, UAC or multiple users.** CI runners are disposable
virtual machines that run as administrators with UAC disabled; anything that depends on UAC prompts, filtered
tokens or a real user's machine is validated separately and recorded as such.

## Scope and limits

* In scope: PowerShell remediation (R1-R4), tests and test infrastructure in isolated environments,
  documentation (worktree roadmap, changelog, release notes), the release candidate package.
* Out of scope: real deletion (the release gate stays `$false`), V0.2 features (Git diagnostics), new product
  features, architectural changes, changes to public contracts beyond what R1 requires (backward compatible).
* Every code change goes through a small pull request with the full suite on Windows PowerShell 5.1 and
  PowerShell 7, the commit identity check, the privacy scan and the static analysis report.
* Merges: fast-forward of the validated pull request head (keeps the noreply identity); never force-push, never
  change the protection of `main`.

## Stop conditions (HUMAN_GATE)

Any of these stops the work and asks the maintainer: a real administrative operation outside a disposable
environment; a change to ACLs, ownership, services or configuration of a real Windows installation; deleting real
files; reducing a security check or bypassing CI; an unplanned architectural or public-contract change; a
persistent failure or a mandatory validation that cannot be done; publishing a tag or release; a remote action
outside this plan.

## Risks and rollback

| Risk | Mitigation | Rollback |
|---|---|---|
| A remediation changes behaviour | Small PRs, full suite on both shells, no engine decision touched | Revert the merge commit range with a new commit (no force-push) |
| Renaming `$Profile` breaks third-party providers | Providers are invoked positionally; test with the old parameter name | Revert R1 |
| CI installation test leaves state | Only in disposable runners; the job never runs on a real machine | Not applicable (VM discarded) |
| UAC behaviour differs from the documentation | T3 on a real machine before claiming it | Correct the documentation; record `NOT TESTED` |
| Release candidate built from a dirty tree | Build from `git archive` of the identified commit only | Rebuild |
