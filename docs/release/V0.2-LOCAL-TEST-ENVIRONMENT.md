# V0.2 local test environment: failure matrix (P5-B)

A maintainer workstation (Windows 10 Pro 22H2 19045, pt-BR, Windows PowerShell 5.1, not elevated, profile name with a
non-ASCII character) showed **36 FAIL** in a full local run of `tests\Run-Tests.ps1 -SkipHeavy` at `6524a31` (P5-A),
while the CI runners pass the same commit (218 PASS / 0 FAIL / 2 NOT TESTED on both shells). This record classifies
them. Nothing on the machine was changed to investigate or to make tests pass: no ACL, profile, TEMP folder, console or
Windows setting. Profile names, SIDs and paths are omitted here.

## Causes found

| Class | Cause (observed read-only) | Defect? |
|---|---|---|
| **ENC** | With output redirected, Windows PowerShell decodes native and child-process output with the OEM code page (850): the profile path in Git output, and accented text printed by the CLI (which writes UTF-8), were misread by the test harness, and the headless TUI fell back to ASCII. Reproduced with a throwaway repository: the same `git rev-parse --show-toplevel` matches the long path under code page 65001 and does not under 850. The product decodes Git output as UTF-8 explicitly and was not affected. | **Test-harness defect**, fixed in P5-B: the suite decodes native output as UTF-8 for its own process (restored at the end). |
| **ACL** | The profile's TEMP folder grants Modify (explicit) and Full Control (inherited) to other local accounts. The test sandbox lives under TEMP and inherits that; the product reports it (`ESCRITA_CONCEDIDA_A_TERCEIROS`, "unsafe parent directory") and its gates block, as designed (fail closed). | **Environmental; product correct.** Not fixable without changing ACLs, which is out of bounds. |
| **TEST** | A P5-A test checked the key footer on the busy frame, which has none. | **Test defect**, fixed in `6524a31`. |

## Result

  whose TEMP folders are private.

  cause); recommended for FINAL-B on a disposable account or machine.
