# Agent Temp Manager 0.1.0: release notes (candidate)

**Status: release candidate, not published.** Publication (tag `v0.1.0` and GitHub Release) is a separate step that
needs the maintainer's explicit authorization.

## What it is

Read-only auditing and preview of the temporary directories that AI coding agents leave on Windows, across every
local user profile, with an interactive dashboard (TUI). V0.1 provider: Claude Code.

**Real deletion is disabled in this release.** `agent-temp clean` runs every safety gate and prints the exact plan,
then stops without deleting anything (`EXCLUSAO_REAL_DESABILITADA_V0_1`, or earlier if a gate blocks).

## Install and verify

1. Download `agent-temp-manager-0.1.0.zip` and `SHA256SUMS.txt`; compare
   `(Get-FileHash .\agent-temp-manager-0.1.0.zip -Algorithm SHA256).Hash` with `SHA256SUMS.txt`.
2. Extract into a folder only administrators can write (for example under `%ProgramFiles%`).
3. From an elevated PowerShell started with `-NoProfile`, run `install\Install-AgentTempManager.ps1`
   ([docs/INSTALL.md](../INSTALL.md), [docs/ELEVATION.md](../ELEVATION.md)).
4. Open a new terminal: `agent-temp verify`, `agent-temp`.

## Known limitations

* **Deletion disabled.** By design in V0.1.
* **Process coverage on real machines.** Protected Windows processes are never inspectable, even elevated (17 on
  the CI runner), so the coverage gate blocks every candidate on a typical machine: in V0.1 cleanup stops before the
  release gate is even reached. V0.3 needs a reviewed design decision on known protected system processes before
  real deletion can ever be enabled.
* **Audit visibility.** An unresolvable `ProfilesDirectory` hides residual profile folders without a note, and an
  unreadable volatile environment makes `%LOCALAPPDATA%`/`%APPDATA%` fall back to default folders
  ([SECURITY-MODEL.md](../SECURITY-MODEL.md), Known limits). Deletion safety is not affected.
* **UAC-dependent behaviour** is documented ([ELEVATION.md](../ELEVATION.md)); the consent, cancellation and
  filtered-token rows were run on Windows 10 x64, while credentials of another account, a real non-interactive
  session, PowerShell 7 as starting shell and Windows 11 x64 are not tested (see the privilege matrix above).
* **Clean environment on a maintainer machine** (Windows Sandbox / fresh VM) not run; replaced by the disposable CI
  installations above.
* Scripts are not Authenticode-signed; integrity relies on `SHA256SUMS.txt` and the installed manifest.
* Other limits (TOCTOU window, unobservable handles, allocation estimate): [SECURITY-MODEL.md](../SECURITY-MODEL.md).
